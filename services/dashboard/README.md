# services/dashboard

Blueprint §10's "Dashboard" domain formally depends on Goals, Roadmap, Check-ins, and Progress. Goals and Roadmap now exist (Check-ins/Progress are still surfaced separately on Dashboard/Goals rather than folded into `NextAction`) - `assembleGoalCards()`-equivalent logic and a deterministic `getNextActions()`-equivalent heuristic, both computed purely from real `Goal` and `Roadmap` data (via the `GoalsView`/`RoadmapsView` interfaces, satisfied structurally by the real `GoalService`/`RoadmapService`).

Deliberately not built: a check-in call-to-action folded into `NextAction` (Check-ins/Progress stay their own Dashboard sections, not part of the heuristic), and `buildCoachSummaryInput()`/an AI coach summary (no AI integration - same reasoning as Profile's deferred `buildSafeProfileContext()` and every other AI-dependent piece so far). `NextAction` is a rule-based heuristic over Goals+Roadmap data, not AI-generated - see `nextAction.ts`'s own comments for the exact rules and their priority order.
